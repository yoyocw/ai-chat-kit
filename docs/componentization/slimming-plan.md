# AI Chat Kit 项目精简

日期：2026-10-02。依据用户“优化整个项目代码，现在还是太重”的指令执行，沿用已讨论的框架移出方向。

## 目标与约束

公开主工程只保留聊天契约、引擎、Starter、Web/JDBC、工具授权协议及按需宿主适配。减少源码、模块和无关版本管理，不以减少安全检查或删除已支持接入模式实现精简。不承诺本次带来尚未测量的运行性能提升。

继续支持 Java 8 / Spring Boot 2.7、JAR + `@EnableAiChatKit` + 配置、启停重启生效、单聊/群聊/停止/历史/分享及身份和租户隔离。保留当前若依适配代码。原业务工程只读，真实业务联调维持暂缓。用户已授权优化验证后推送公开仓库；现有公开 Preview 的标签和附件保持原样。

## 当前基线

计数范围：组件、framework、依赖 BOM、FAC、示例、脚本、SQL、根 POM/README；排除生成物和内部证据。共 834 文件、753 Java 文件、32 个 POM；BOM 859 行、108 个依赖声明、62 个属性。逐文件 SHA 与完整备份在本地忽略的验证目录保存。

## 实施路径

1. 将 MCP JWT 协议模块移到 components，保持其 Maven 坐标和公开类型不变，移除 framework 聚合层。
2. 宿主适配消除平台兼容和 legacy-api 的编译依赖。保留 in-process 与 ordinary-bearer 模式；本地登录类型通过受控原生桥读取，远程查询只保留必要协议与严格 HTTPS 客户端。身份、权限、租户、令牌期限和异常脱敏规则保持。
3. 将 11 个平台兼容模块、legacy API/server 和 FAC 从主源码移到本地保留档案；保留逐文件清单，不删除旧历史，不将档案纳入新构建或分发。
4. BOM 只管理保留模块实际需要的依赖，移除无关 Cloud/平台/业务组件版本与仓库配置。保留宿主适配所需的 provided 依赖和中立组件的独立解析能力。
5. 精简 README、接入样例和制品验证脚本，清楚区分默认组件与可选宿主；保留原 LICENSE，历史证据不回写为本轮结果。
